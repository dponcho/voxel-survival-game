## Native records and ownership

The additional trace is a fixed binary file, limited to **32 MiB including its
40-byte header**. Each 192-byte little-endian record retains the span ID, direct
parent, OS thread ID, worker-incarnation lane, slot, start/end/submission section,
completion flag, units/bytes and four raw current-thread counter stamps. Each
stamp retains availability, success, error and monotonic wall brackets. Failed
counter payloads decode as null, never as measured zero. Counter values stay
unsigned 64-bit integers in binary and decimal strings in derived reports.

| --- | --- | --- |
| 1 | Preparation qualification queries | Once per loading callback; terrain/native readiness queries |
| 2 | Gameplay resource/native queries | One child of each callback-output span |
| 3 | Frontier scan/evaluation | One child of each callback-output span |

| 9 | Worker qualification writes | One child per CSV/edit output item; actual UTF-8 payload bytes |
| 10 | Operational proxy writes | Separate children, preserving all 72 saves and actual UTF-8 bytes |
| 11 | Worker flush | Child of the writer lifetime |
| 12 | Intermediate shared boundary snapshot | Prepared/+X/-X/+Z; start precedes recorder setup and final boundary follows recorder drain |

The four stamps are begin-API entry/exit and end-API entry/exit. For one span,
`full = end_exit - begin_entry`, `body = end_entry - begin_exit`, and enclosed
`bookkeeping = full - body`. Exclusive body subtracts direct children's full
spans once on the same lane. The independent reader requires the exact identity
`sum(root full) = sum(exclusive body) + sum(bookkeeping)` per lane. Parent and
child costs are never both added as work; thread totals are never added to the
complete process observation.

Each worker receives a unique lane even if Windows later reuses its OS thread
ID. The worker records its final stamp after its files close and before exit;
the main thread retains an enclosing process observation after join. Thread
bootstrap/teardown outside that captured window remains unattributed process
work. Main-thread spans cannot cross sections. Workers retain submission/start/
end sections and crossings are reported separately instead of assigned wholly
to one route leg.

Main/flush/lifetime per-span byte fields are reserved, not measured zero; derived
reports mark those bytes unavailable. Existing raw cycle/pose files and writer
records preserve complete output sizes. Worker write spans retain actual bytes
and reconcile against their three phase output files and native completion
counts. No byte-to-CPU model or callback normalization is applied.
